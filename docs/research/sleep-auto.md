# SLEEP-AUTO MODE

이 모드가 활성화되면, 기본 CLAUDE.md의 "매 명령마다 사용자 확인" 규칙을 이 세션에 한해 **무시(override)**한다. 사용자는 자고 있다. 막히면 멈추지 말고, 가장 합리적인 선택을 하고 기록한 뒤 계속 진행한다.

## 작업 안전 규칙 (절대 준수)
- 현재 체크아웃된 `지능형` 브랜치에서만 작업한다. `main` 및 모바일프로그래밍 브랜치는 절대 건드리지 않는다.
- `git push --force`, `reset --hard`, 파일/디렉터리 대량 삭제 등 파괴적 명령 금지.
- 기존 파일을 덮어쓰기 전에는 항상 새 파일/폴더로 분리 생성한다.
- 각 단계(Phase)가 끝날 때마다 의미 있는 메시지로 `git commit` 한다. (push는 하지 않는다)
- 비밀키/토큰을 코드나 로그에 남기지 않는다.

## 자율 판단 규칙
- 사양이 모호하면: 가장 단순하고 표준적인 선택을 하고, 그 가정을 `DECISIONS.md`에 한 줄로 기록한 뒤 진행한다.
- 외부 다운로드/네트워크 실패 시: 멈추지 말고 대체 경로 → 그래도 안 되면 합성 데이터 fallback으로 전환하고 `DECISIONS.md`에 기록한다.
- 사람의 판단이 꼭 필요한 사항(예: 평가 라벨 정의 변경): 코드를 막지 말고 합리적 기본값으로 진행하되, `QUESTIONS.md`에 "왜 물어보는지 + 내가 임시로 택한 값"을 적는다.
- 코드는 "작성 완료"가 아니라 "실행해서 통과 확인"까지를 완료로 본다. 최소 1회 실제 실행/스모크 테스트한다.

## 로그 파일 (반드시 유지)
- `WORKLOG.md`: 시간순 작업 기록.
- `DECISIONS.md`: 내가 내린 가정과 선택.
- `QUESTIONS.md`: 아침에 사용자가 답해야 할 것 (우선순위 표시).
- `SUMMARY.md`: 마지막에 작성하는 아침 브리핑 — 무엇을 했고, 무엇이 되고, 무엇이 남았고, 어떻게 실행하는지.

## 우선순위 원칙
완결성 > 정교함. 먼저 가장 단순한 end-to-end 파이프라인을 끝까지 돌려 결과를 낸 뒤, 남는 시간에 고도화(추가 모델, 튜닝, ablation)를 한다.
